# Deployment (AWS)

Region used throughout: **ca-central-1** (Canada Central). Everything here is optional for local development.
Status: templates are validated offline with `cfn-lint`; **they have not been deployed to a real account yet**.

## 0. One-time setup
1. Create an AWS account. Do not use the root user for daily work: in **IAM Identity Center** (or IAM) create an
   admin user for yourself and turn on **MFA**.
2. Set a spending alarm: **Billing → Budgets → Create budget** → "Monthly cost budget", e.g. US$10, email alert.
3. Install and sign in the AWS CLI on your machine:
   ```bash
   brew install awscli
   aws configure sso          # or: aws configure   (access key for your admin user)
   aws sts get-caller-identity   # prints your account id when sign-in works
   ```
   Never paste AWS keys into chat, code, or `.env`. They stay in `~/.aws/`.

## Stage 10 — Amazon Aurora PostgreSQL

What gets created:

| Resource | Why |
|---|---|
| VPC `10.20.0.0/16`, 2 public + 2 isolated database subnets in two Availability Zones | Database subnets have **no route to the internet** |
| Security group `civictax-app` | Worn by the application (Stage 14) |
| Security group `civictax-database` | Allows PostgreSQL (5432) **only from `civictax-app`**; no outbound |
| Aurora PostgreSQL 17, Serverless v2, 0–1 ACU | Pauses after 5 idle minutes, so an unused demo costs storage only |
| Secrets Manager secret (created by RDS) | Master password is generated by AWS; nobody ever types or sees it |
| Encryption at rest, `rds.force_ssl=1`, 7-day backups, PostgreSQL logs to CloudWatch | Baseline security |

### Option A — CloudFormation (recommended: repeatable, one command to delete)
```bash
# 1. Network (about 1 minute)
aws cloudformation deploy --region ca-central-1 --stack-name civictax-network --template-file infra/network.yaml

# 2. Which Aurora PostgreSQL 17 versions does the region offer? Pick the newest.
aws rds describe-db-engine-versions --region ca-central-1 --engine aurora-postgresql \
  --query "DBEngineVersions[?starts_with(EngineVersion,'17')].EngineVersion" --output text

# 3. Database (10–15 minutes). Replace 17.5 if step 2 shows something newer.
aws cloudformation deploy --region ca-central-1 --stack-name civictax-database \
  --template-file infra/database.yaml --parameter-overrides EngineVersion=17.5

# 4. What was created: endpoint, port, database name, secret ARN
aws cloudformation describe-stacks --region ca-central-1 --stack-name civictax-database \
  --query "Stacks[0].Outputs[].[OutputKey,OutputValue]" --output table
```

### Option B — the same thing by hand in the AWS Console
1. Top-right region menu → **Canada (Central) ca-central-1**.
2. **VPC → Create VPC → "VPC and more"**: name `civictax`, IPv4 CIDR `10.20.0.0/16`, Availability Zones **2**,
   public subnets **2**, private subnets **2**, NAT gateways **None**, VPC endpoints **None** → Create VPC.
3. **EC2 → Security Groups → Create security group** (twice, both in the `civictax` VPC):
   - `civictax-app`: no inbound rules.
   - `civictax-database`: inbound rule type **PostgreSQL**, source = the `civictax-app` security group.
     Then delete its default outbound rule.
4. **RDS → Subnet groups → Create DB subnet group**: name `civictax`, VPC `civictax`, both AZs, the two **private** subnets.
5. **RDS → Databases → Create database**:
   - **Standard create** → **Aurora (PostgreSQL Compatible)** → newest **17.x** version → template **Dev/Test**.
   - DB cluster identifier `civictax`; master username `civictax_admin`;
     credentials **Managed in AWS Secrets Manager**.
   - Instance configuration **Serverless v2**: minimum **0 ACU** (pause after 5 minutes), maximum **1 ACU**.
   - Availability: **Don't create an Aurora Replica**.
   - Connectivity: **Don't connect to an EC2 compute resource**; VPC `civictax`; subnet group `civictax`;
     **Public access: No**; security group `civictax-database` (remove `default`).
   - Additional configuration: initial database name `property_tax`; **encryption enabled**; backup retention 7 days;
     log exports **PostgreSQL log**; deletion protection as you prefer → **Create database** (10–15 minutes).
6. **RDS → Databases → civictax → Configuration**: note the **writer endpoint** and the **master credentials ARN**.

### How the backend connects (wired up in Stage 14 on ECS)
| Setting | Value |
|---|---|
| `DB_HOST` / `DB_PORT` / `DB_NAME` | writer endpoint / `5432` / `property_tax` |
| `DB_USERNAME`, `DB_PASSWORD` | injected by ECS from the Secrets Manager secret (`<arn>:username::`, `<arn>:password::`) |
| `DB_URL_PARAMS` | `?sslmode=verify-full&sslrootcert=/app/rds-ca.pem` (the CA bundle is baked into the backend image) |
| `DEV_AUTH` | **unset**. Use `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI` (Cognito) instead |

- **Migrations:** Flyway runs the same `V1__initial_schema.sql` on startup; nothing is applied by hand.
- **First request after a pause** waits 15–30 s while Aurora resumes. That is expected with 0 ACU.
- **Connectivity proof** happens in Stage 14, when the ECS task (wearing `civictax-app`) starts and migrates.
  Optional earlier check, not yet tried by this project: open **CloudShell → Actions → Create VPC environment**
  (VPC `civictax`, security group `civictax-app`) and connect with `psql "host=<endpoint> dbname=property_tax
  user=civictax_admin sslmode=require"`, pasting the password from the secret.

### Cost (rough; confirm on the AWS pricing pages)
Paused: storage only (cents per month for this data). Running: billed per ACU-hour while active, at most 1 ACU.
Secrets Manager: about US$0.40 per secret per month. VPC, subnets and security groups are free; there is no NAT
gateway. Aurora is **not** in the free tier, so delete the stacks when you are finished.

### Clean up
```bash
aws cloudformation delete-stack --region ca-central-1 --stack-name civictax-database
aws cloudformation wait stack-delete-complete --region ca-central-1 --stack-name civictax-database
aws cloudformation delete-stack --region ca-central-1 --stack-name civictax-network

# Deleting the database stack keeps one final snapshot (so data is never lost by accident). Remove it to stop charges:
aws rds describe-db-cluster-snapshots --region ca-central-1 --snapshot-type manual \
  --query "DBClusterSnapshots[].DBClusterSnapshotIdentifier" --output text
aws rds delete-db-cluster-snapshot --region ca-central-1 --db-cluster-snapshot-identifier <name-from-above>
```

## Stage 11 — Amazon S3 document storage

Locally nothing is needed: `compose.yaml` runs an S3 emulator (`adobe/s3mock`) and the backend talks to it because
`S3_ENDPOINT` is set. In AWS, leave `S3_ENDPOINT` **unset** and the same code uses real S3.

What `infra/storage.yaml` creates:

| Resource | Why |
|---|---|
| Bucket `civictax-documents-<account>-<region>` | All four **Block Public Access** settings on, ACLs disabled, default encryption, versioning, old versions expire after 90 days |
| Bucket policy | Denies any request not made over TLS |
| IAM managed policy | `s3:GetObject` + `s3:PutObject` on `tax-bills/*` and `reports/*` only. No list, delete, or bucket administration. Attached to the ECS task role in Stage 14 |

```bash
# The template creates an IAM policy, so CloudFormation asks you to acknowledge that explicitly.
aws cloudformation deploy --region ca-central-1 --stack-name civictax-storage \
  --template-file infra/storage.yaml --capabilities CAPABILITY_IAM

aws cloudformation describe-stacks --region ca-central-1 --stack-name civictax-storage \
  --query "Stacks[0].Outputs[].[OutputKey,OutputValue]" --output table
```

Backend settings in AWS: `DOCUMENTS_BUCKET=<DocumentsBucketName output>`, `AWS_REGION=ca-central-1`, no
`S3_ENDPOINT`, no access keys (the task role provides credentials).

By hand in the console instead: **S3 → Create bucket** (region Canada Central; ACLs disabled; **Block all public
access** on; versioning enabled; default encryption SSE-S3) → **Permissions → Bucket policy**: deny when
`aws:SecureTransport` is false → **IAM → Policies → Create policy** with the two actions and two prefixes above.

Cost: S3 storage and requests for a few small PDFs are fractions of a cent per month.

Clean up (the bucket is kept on stack deletion, so empty and remove it yourself):
```bash
aws cloudformation delete-stack --region ca-central-1 --stack-name civictax-storage
BUCKET=civictax-documents-$(aws sts get-caller-identity --query Account --output text)-ca-central-1
aws s3api delete-objects --bucket "$BUCKET" --delete "$(aws s3api list-object-versions --bucket "$BUCKET" \
  --query '{Objects: [Versions,DeleteMarkers][][].{Key:Key,VersionId:VersionId}}' --output json)"   # skip if the bucket is empty
aws s3api delete-bucket --bucket "$BUCKET" --region ca-central-1
```
